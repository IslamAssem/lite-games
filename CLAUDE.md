# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

"Lite Puzzles - Mini Games" is a collection of small classic logic puzzles in the style of old flash games: river crossing, water jugs, the Tower of Hanoi and similar. It has a single `:app` module, package `com.islamassem.litepuzzles`, and is built entirely with Jetpack Compose. `MainActivity` is the only Activity. Use classic folk puzzles and generic names, not trademarked product names.

## Architecture

- **`engine/`**: game logic with no UI. `Puzzle<S, M>` is a pure state machine: `initialState`, `legalMoves`, `apply`, `status` (Playing/Won/Lost(reason)), `describe(move)` and `solve(from)`. `solve` defaults to `BfsSolver`; override it for state spaces too large for breadth-first search. Legal moves must include *losing* moves, because players need to be able to make mistakes; the solver skips lost states. States must be immutable data classes, since the solver uses them as hash keys. `PuzzleSession` wraps a puzzle with undo/redo history, hints (the next move of a shortest solution), and star ratings compared against the optimal move count. Its fields are Compose snapshot state.
- **`catalog/`**: `GameEntry` holds what the home screen needs (id, title, emoji, category, difficulty) plus a `content: @Composable (onExit) -> Unit`. `GameRegistry.games` is the **single list of games**. Ids must be unique (checked when the registry loads) and must never change once shipped.
- **`ui/game/PuzzleScreen`**: the standard screen for any engine-based puzzle. It provides the top bar, a rules dialog, the move counter, undo/redo/restart/hint, and the win/lose dialogs. Each game supplies only the board composable `(session, modifier)`.
- **`games/<family>/`**: each puzzle family has its own package. `rivercrossing/` is the reference example. `RiverCrossingPuzzle` is generic (passengers, boat capacity and `BankRule`s are checked on both banks after every crossing), and each level in `RiverCrossingLevels` is just configuration.
- **Animating moves:** boards animate a move *before* it is committed, by calling `session.playAnimated(move) { /* suspend animations */ }`. While it runs, `isAnimating` locks undo/redo/restart/hint, and the state (and any win/lose dialog) changes only after the animation finishes. Each board keeps its own `Animatable`s (boat position, water levels, disc offsets) and snaps them to the committed state in a `LaunchedEffect(state)`, so undo and restart jump instantly. The user specifically asked that objects never reach their destination before the animation shows them getting there.
- **Families so far:** `rivercrossing/`, `pouring/` (`WaterJugsPuzzle`: jug sizes, optional tap and drain, goal predicate), `hanoi/` (`HanoiPuzzle(discCount)`, three pegs), `sliding/` (`SlidingTilesPuzzle`, n×n, randomly scrambled) and `lights/` (`LightTogglePuzzle`, n×n, random board).
- **Solvers:** `BfsSolver` is the default. `AStarSolver` is for larger spaces that have an admissible heuristic; sliding tiles uses Manhattan distance, which is fine for 3×3 but too slow for 4×4. Light Toggle overrides `solve` with exact GF(2) Gaussian elimination, because BFS can't handle 2^25 states. Some 5×5 light patterns are unsolvable, so random boards are generated by pressing cells on a dark board. Scrambles are generated the same way, as random legal moves from the solved state, so they are always solvable.
- **Random games:** pass `randomized = true` to `PuzzleScreen` and deal a new puzzle inside `createPuzzle`. The win dialog then shows "New puzzle", which calls `createPuzzle` again inside `key(deal)` and resets all of the board's remembered state.
- **Navigation** (`MainActivity.App`) is a single `rememberSaveable` id of the open game: null shows the home list. There is no navigation library.

**Adding a game:** add a new level to an existing family (configuration only), or write a new `Puzzle` together with a board composable that uses `PuzzleScreen`. Then add its `GameEntry` to `GameRegistry`. Add a unit test that calls `solve(initialState)`, to prove the level can be won and to pin its optimal move count (see `RiverCrossingPuzzleTest`).

**Known gap:** `PuzzleSession` is created with `remember`, so progress inside a game is lost when the device rotates. Saved progress and best scores are not implemented yet.

## Commands

Run from the repo root (on Windows use `.\gradlew.bat`, or `./gradlew` from Git Bash):

```
./gradlew assembleDebug                 # build debug APK
./gradlew installDebug                  # install on connected device/emulator
./gradlew test                          # JVM unit tests (app/src/test)
./gradlew connectedAndroidTest          # instrumented tests on a device (app/src/androidTest)
./gradlew lint                          # Android lint
./gradlew :app:testDebugUnitTest --tests "com.islamassem.litepuzzles.ExampleUnitTest"          # single test class
./gradlew :app:testDebugUnitTest --tests "com.islamassem.litepuzzles.ExampleUnitTest.addition_isCorrect"  # single test method
```

## Build configuration

- **AGP 9.x with built-in Kotlin**: AGP 9 compiles Kotlin itself, so the `org.jetbrains.kotlin.android` plugin is not applied and should not be added. The only Kotlin plugin is the Compose compiler (`org.jetbrains.kotlin.plugin.compose`). Its version is the `kotlin` entry in the version catalog.
- Inside `buildList { }`, an unqualified `size` refers to the list being built, not to a puzzle's `size` property. This already caused one bug. Copy the property to a local first.
- `core-ktx` is pinned to 1.18.0 because 1.19.x requires compileSdk 37, which isn't installed. Check this before bumping AndroidX versions.
- Compose versions come from the Compose BOM. Material icons are not a dependency; the UI uses text and emoji glyphs instead.
- Dependencies and plugin versions are centralized in `gradle/libs.versions.toml`; reference them via `libs.*` aliases rather than hard-coded coordinates. Repositories are declared only in `settings.gradle.kts` (`FAIL_ON_PROJECT_REPOS`), so don't add `repositories {}` blocks in module build files.
- `compileSdk` 36 (minor API level 1, via the new `release(36) { minorApiLevel = 1 }` DSL), `targetSdk` 36, `minSdk` 24, Java/JVM target 11.
- The XML theme `Theme.LitePuzzlesMiniGames` (`DayNight.NoActionBar`) only covers the window. All UI colors come from `ui/theme/LitePuzzlesTheme` (Material 3).
- **Icon & store art are generated** by `python store/generate_assets.py` (Pillow + numpy): it writes the adaptive-icon vectors (`drawable/ic_launcher_{background,foreground,monochrome}.xml`), the legacy PNG mipmaps for API 24–25, `store/play-icon-512.png` and `store/feature-graphic-1024x500.png`. Edit the geometry/colours in the script, not the generated files. `--frames` turns raw emulator captures in `store/screenshots/raw/` into captioned 1080×1920 store screenshots in `store/screenshots/phone/` (captions keyed by file name in `CAPTIONS`).
- The release build type references `proguard-rules.pro`, but that file does not exist yet in `app/` — create it before enabling minification.
